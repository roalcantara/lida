# lida v0.1.1: every known fix

## Intent

v0.1.0 is installed by the dots Brewfile and manages this repository's own `TODO.md`. A command audit
(`/private/tmp/lida-audit-2026-11-24.md`, findings #1–#19) and dots' own migration found bugs, seven of them losing data.
v0.1.1 is one patch release that fixes every known bug, so the latest v0.1.x is "stable" in the roadmap's sense: all
features work and no bug is known. dots then bumps its pin, regenerates its zsh completion as `_lida`, and drops todo-cli.

## Goals

- Every task tagged `v0.1.1` in `TODO.md` is done (24 at the time of writing; `lida list -t v0.1.1`).
- No write can lose or corrupt data: every data-loss finding has a test that fails on v0.1.0 and passes now.
- Output and behaviour changes are intentional, one per commit, each with its snapshot diff and its DESIGN.md update.
- The release is a patch: every commit is `fix`, `docs`, `test`, `ci`, `build`, `chore` or `ref`. No `feat`.

## Non-goals (v0.2, tagged there)

The `created` stamp, `-t/--tags`/`--tag` aliases, empty-value clearing (#12), commas inside tags (#13), keeping YAML
comments (#16), duplicate-tag counting and `meta unset` reporting (#17).

## Anti-goals

- Breaking existing files: every `TODO.md`/`TODO.yaml` that v0.1.0 reads must still load and round-trip.
- Changing the `--json` shape (keys and nulls stay as they are: agents depend on it).
- A commit-body line starting with "breaking change" (the changelog parser reads it as one: AGENTS.md).

## Constraints

- TDD per fix: the failing test first, then the fix. Snapshots change only in the commit whose fix changes them.
- `lida-core` stays free of CLI, colour and binary crates (`core-purity`).
- Real files as compatibility fixtures: this repo's `TODO.md`, `~/Work/toma/TODO.md` (todo-cli format, `Created`
  lines), and the dots `TODO.yaml` files under `~/.local/share/dots` (copied into test fixtures, not read in place).

## Approaches (decided)

- **One release, one commit per fix** (chosen) vs. several smaller patch releases: dots takes one pin bump.
- **#1 the file lida stops writing:** deleted (chosen) vs. kept and ignored. A stale copy misleads every reader that
  looks for `TODO.yaml` first (dots' `/wip:resume` probe does); git keeps history.
- **#2 multi-line text:** rejected with an error (chosen) vs. an escaping scheme in Markdown (a format change).
- **#4 unknown Markdown content:** reading still works; saving refuses (chosen) vs. failing every command on load.

## Decided design, fix by fix

Errors below are the exact copy (lower-case first word, `error: ` prefix from `main`), exit 1.

### CLI surface (dots findings)

1. **Completion from the declaration.** Replace the hand-written `Completion` subcommand and
   `crates/lida/assets/raw_todo_completion.zsh` with usage-rs's built-in one (`#[usage(completion)]` on `LidaCli`,
   `usage_rs::completion::Completion`, printed with `run_split` so stdout carries only the script). Supported shells
   and `--install` come from usage-rs; an unsupported shell is a parse error (exit 2). The script calls `lida` back
   for words (`lida __complete_word__`), so no external tool is needed. **Parity with dots (builder-check call):** dots'
   patched todo script completed task IDs, tags, priorities, statuses and `cwi` formats; lida declares the same through
   usage-rs completers (`complete = …`), not `choices` (which would turn a bad value into exit 2 and bypass fix 16's
   copy and the status aliases). Statuses complete canonical names only. Restoring what the shipped completion offered is
   a fix. Tests: `completion zsh` starts with `#compdef lida` and contains no `todo`; `lida __complete_word__` (zsh)
   offers `add`'s long flags, the fixture's task IDs after `done`, its tags after `list -t`, `low medium high none` after
   `-p`, and `todo in-progress done blocked` after `status <id> --set`.
2. **`lida usage` prints the full spec:** `LidaCli::to_kdl()`. `lida.usage.kdl` at the root is regenerated from it,
   and a test asserts the file equals `lida usage` (so it cannot drift). `release:version` keeps editing its
   `version` line.
3. **TODO.yaml writes no empty keys.** In the YAML writer only (JSON untouched): for tasks, drop `due`, `created`,
   `position`, `blocked_reason`, `priority` when null and `actors`, `comments`, `tags` when empty. Meta values are
   never touched (a JSON `null` in meta stays). Test: a hand-written YAML without those keys, after `lida start`, differs
   only in the started task's `status` line.
4. **Colour only on a terminal.** Colour is on when stdout is a terminal and `NO_COLOR` is unset; `CLICOLOR_FORCE=1`
   forces it (for tests and pagers). Decided once in `main` (`owo_colors::set_override`); the `error` label follows
   stderr's own terminal check. Snapshots (piped) lose their ANSI codes; one snapshot runs with `CLICOLOR_FORCE=1` to
   keep the colours pinned.
5. **Aligned columns:** pad each cell to its width before colouring it.

### Data loss (audit)

6. **#1 Format switches leave one source of truth.** `cwi md`: write `TODO.md`, then delete `TODO.yaml`. `cwi yaml`:
   write `TODO.yaml`, delete `TODO.md`. `cwi both` writes both. `init --force` deletes the file of the other format.
   `Store::load` follows the configured format when both files exist (`MdOnly` reads `TODO.md`); with no config,
   both files mean dual-write with `TODO.yaml` authoritative, as today. **A switch never loses data (builder-check
   call):** `cwi md` refuses when the document holds what Markdown cannot (actor `actor_type`/`pic`, task or comment
   `actors`, `extra` fields): `error: TODO.md cannot hold <what> (task #<id>): stay on yaml or both`; `cwi yaml` refuses
   when `TODO.md` has lines lida does not recognise (fix 9). Nothing is written or deleted when it refuses. Tests: the
   audit's two repros; `cwi md` on the dots blog `TODO.yaml` (`actor_type`) refuses and leaves both files as they were.
7. **#2 Single-line text.** Every text lida writes into `TODO.md` rejects `\n` or `\r` (builder-check call: all of
   them, not four): description, comment, blocked reason, `--project`, tags, `--position`, `--due`, meta keys and
   string meta values: `error: <field> must be a single line`. A project name containing `-->` is rejected too
   (`error: project name cannot contain '-->'`).
8. **#3 Comment links in TODO.md.** Each task with comments gets `  - **Comments**: <id>, <id>` (after its other
   fields); the parser sets each comment's `task_id` from it. Files without the line still load (links empty, as in
   v0.1.0). Test: `add --task-id X -c note` in Markdown mode, then `show X --json` lists the comment and `delete X`
   removes it.
9. **#4 Unknown Markdown content.** The parser records lines it does not recognise (anything but blank lines, the
   project comment, the three section headings, task lines, known field lines, meta items, actor and comment
   entries). Reading works; `save` refuses with `error: TODO.md line <n> is not something lida writes: <line>`.
   Tests: the real files load and save with **the same parsed document** (load → save → load is equal); this repo's
   `TODO.md`, which lida wrote, also stays **byte-identical**. Fixtures: this repo's `TODO.md`, toma's `TODO.md`
   (todo-cli field order is rewritten to lida's; the data is unchanged), and the dots `TODO.yaml` files for the YAML
   side. A file with a stray paragraph refuses to save. (Builder-check call: byte-identity for toma's order or the dots
   files' explicit nulls would need order-preserving parsing, a model change.)
10. **#5 Meta keys:** `meta set` rejects keys containing `:` (`error: meta keys cannot contain ':'`).
11. **#6 Project names:** the header keeps everything between `todo-project:` and `-->`, trimmed.
12. **#7 Duplicate IDs:** loading fails with `error: duplicate task ID #<id> in <file>`.

### Wrong results (audit and known)

13. **#8 and #11 One status parser.** `list -s`, `status --set` and the file formats share one function (core:
    `Status::parse`), accepting the canonical names and every alias with `-`, `_` or no separator.
14. **#9 One config file:** read and write `.lida/config` if it exists, else `.todo/config` if it exists, else create
    `.lida/config`.
15. **#10 Conflicting init flags:** more than one of `--yaml`, `--md`, `--both` →
    `error: choose one of --yaml, --md or --both`.
16. **Priorities:** an unknown value is `error: invalid priority '<v>'. Valid values: low, medium, high, none`; `none`
    clears it (the only way to clear one once invalid values stop doing it silently). **Filters too (builder-check
    call):** `list -s` and `list -p` take the same parsers, so a typo errors (exit 1, same copy) instead of silently
    matching nothing, which is how #8 hid; `list -p none` lists the tasks without a priority.
17. **`show` prints everything it stores:** `Due:`, `Blocked reason:` and a `Comments:` block (`    #<id> <text>`),
    each only when set, in that order after `Tags`.
18. **Error copy:** every message starts lower-case (`no TODO file found in directory`).

### Docs, build, CI

19. **Docs drift (#14, #15, #18, #19, README `--meta`):** README says `--json` on `list` and `show`; DESIGN.md says
    argument errors exit 2 with usage on stderr; `--help` texts match behaviour; README's Rust floor matches
    `rust-version`; the `--meta` claim becomes `lida meta <id> set <key> <value>`.
20. **Honest `rust-version`:** the lowest toolchain on which `cargo check --workspace --locked` and the tests pass
    (at least 1.88 for let-chains); a CI job `msrv` reads it from `Cargo.toml` and runs `cargo +<it> check` and the
    tests. README states it.
21. **Audit on pull requests:** the `audit` job runs on pull requests too (`plan` stays push-to-main only), so release
    blockers show before merge.
22. **Snapshot version redaction by pattern:** redact only `lida <version>` and `version "<version>"`.

## Order

Data loss first (6–12), then CLI surface (1–5), wrong results (13–18), docs/build/CI (19–22). `TODO.md` tasks close in
the commit that fixes them. One PR; the owner merges; it releases v0.1.1. After it: verify the release as for v0.1.0,
and hand dots the new completion.

## Left to the builder

- Exact field order and wording inside each new `TODO.md` line, as long as old files still parse.
- How the YAML writer drops keys (a `serde_yaml_ng::Value` pass or `skip_serializing_if` behind a YAML-only type),
  as long as `--json` is unchanged.
- Which usage-rs feature flags to enable for completions.
- The `msrv` job's runner and cache.
